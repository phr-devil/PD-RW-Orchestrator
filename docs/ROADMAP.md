# Acceptance-driven roadmap

- **M0 (complete):** runnable minimal Python CLI, versioned contracts, deterministic policy filtering, mocked two-agent DAG and tests.
- **M1-A (code and simulated CI complete):** PD-RW-Agent RC CLI read-only `resume` bridge, privacy-preserving source status; no execution permission.
- **M1-B (code and cross-platform CI complete):** private SQLite scheduling intents, restart-safe unresolved attempts; original science evidence remains authoritative.
- **D1–D3 (this release):** v1/v2 Agent result normalization; conservative next-action decision; ChatGPT Task Contract + handoff JSON/Markdown. Synthetic/offline test only, not evidence of improved scientific reasoning.
- **v0.3 transition contracts (code + simulated CI):** next-task-specific goal, guidance and no inherited effects; explicit existing-scope review; opt-in read-only PD-RW status in advise; typed host dependency port (no live host installed); content-verified private handoff export.
- **M1-C (pending on operator machine):** original project identity/PD-RW-Agent receipts/process-liveness and permission-bound host bridge.
- **M2-Pilot code (current):** real Codex CLI subprocess adapter (one synthetic read-only fixture, explicit two-flag opt-in, 120s wall timeout, schema output, private one-shot intent). CI mocks subprocess and validates end-to-end integration; real Windows acceptance and actual scientific host isolation are still pending.
- **M2 (next real capability):** one true read-only specialist or host Agent adapter, then a second real Agent handoff. Test health, version, accepted capability, output refs, cancellation and budget on real platform. No dummy-adapter successes.
- **M3:** PD-RW-Experience advisory provider; check evidence provenance, time visibility and negative transfer.
- **M4:** paired single vs multi-Agent and with vs without experience evaluation, fixed compute/model budget; measure scientific error, artifact quality, cost and interventions.

Do not duplicate H-stage/science ledger, introduce uncontrolled agent spawning or use Agent self-assessments as permission/scientific truth.

- **R1 correctness (current):** fixed synthetic fixture hash/allowlist, preflight before subprocess, separate prior subprocess observation from next-task dispatch, prevention of repeated review loops, and failure-first decision handling. CI remains mock-provider only.

- **R2-A (v0.5.0, synthetic CI):** compiled scoped pilot Task+Policy actually sent to Codex CLI; bounded local task-contract and observed execution receipt with read-only hash checks; pilot-only provider capability acceptance; CLI preview/inspect without model calls. General routing and host authorization remain fail-closed.
- **R2-B/M1-C (pending):** trusted PD-RW original evidence/grants from operator-controlled host, process liveness, real Agent credentials/usage and independent science review. Only then validate a general-purpose Agent execution path.

- **R2-B v0.6.0 (code + synthetic CI):** exact original project-map membership,
  single read-only resume, scoped original operation receipt and DEV/VAL Run
  source cross-check, sanitized status/metadata, task-ID consistency and
  fail-closed reconciliation in ChatGPT handoff. Not an authority to run DEV.
- **M1-C operator machine (PENDING):** verify actual pinned PD-RW-Agent
  RC/Skill/MCP environment, original author H6/H8 scope, original evidence
  and real OS process liveness. No upgrade to real-project write-enabled tasks
  or autonomous general routing without this separate verified host gate.
